# What is TDD?

**Definition:**
Test-Driven Development is a design loop: write a failing test (red), write the minimum code to pass (green), then refactor while tests stay green. Tests are specified first so they cannot be biased by existing implementation. It is not the same as 'writing tests after' even if coverage is high.

**Key points:**

- Red → green → refactor.
- One failing test at a time.
- Refactor only on green.
- Tests document behavior.
- TDD is a discipline; coverage % is an outcome, not the method.
