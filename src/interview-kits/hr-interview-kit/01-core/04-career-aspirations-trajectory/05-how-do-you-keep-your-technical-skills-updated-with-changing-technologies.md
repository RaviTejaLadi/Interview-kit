# How do you keep your technical skills updated with changing technologies?

### Definition

This question evaluates your **continuous-learning process**.

The interviewer wants to know whether you actively maintain your technical knowledge instead of only learning when your job requires it.

A good answer should mention **how you learn** and **how you validate what you learn**.

### Sample answer

> “I usually use a combination of official documentation, technical articles, open-source projects, and hands-on experimentation.
>
> For technologies I use regularly, I prefer starting with the official documentation because it gives me the most reliable understanding of the current API and recommended patterns.
>
> When I come across a new concept, I usually build a small example or prototype rather than only reading about it. For example, if I'm learning a React performance technique, I'll create a small application and use browser DevTools or React profiling tools to understand its actual behavior.
>
> I also follow changes in the React and JavaScript ecosystems and periodically review release notes so I understand which features are stable and which are still evolving.
>
> Most importantly, I try not to adopt a technology simply because it's new. I first understand the problem it solves, its trade-offs, and whether it actually makes sense for the project.”

### Strong principle

> **Don't chase technologies. Understand problems and evaluate tools.**

For example, instead of saying:

> “I learn every new JavaScript framework.”

Say:

> “I evaluate new tools based on the problem they solve, their maturity, ecosystem, performance characteristics, and how they fit into the existing architecture.”

That sounds much more senior.
