# How do you explain complex technical concepts to non-technical team members or clients?

**Definition:**  
The interviewer wants to know whether you can translate technical concepts into **business impact and simple explanations**.

**Sample answer:**

> I first try to understand what the person actually needs to know. I don't explain every technical detail unless it's relevant to their decision.
>
> For example, if I need to explain why an API response is slow, I wouldn't start by explaining database indexes or query execution plans.
>
> I might explain it using a simple analogy:
>
> "Think of the API as a restaurant. If the kitchen has to search through the entire inventory every time someone orders something, the response takes longer. We can organize the data so the kitchen can find what it needs faster."
>
> Then I explain the actual technical solution only if they need more detail.
>
> I also use diagrams, examples, and before-and-after comparisons when they're useful.
>
> The goal isn't to make the explanation sound technical. The goal is to make sure the other person understands the important concept.

**Good rule:**

> **Explain the impact first → Use an analogy → Show the technical detail only when necessary.**
