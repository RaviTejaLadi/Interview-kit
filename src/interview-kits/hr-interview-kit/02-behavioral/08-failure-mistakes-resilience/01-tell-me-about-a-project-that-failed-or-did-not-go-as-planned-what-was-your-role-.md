# Tell me about a project that failed or did not go as planned. What was your role, and what did you learn?

**Definition:**  
The interviewer wants to see how you respond when things don't work as expected. Focus on your role, what went wrong, what you could control, and what you learned.

**Sample answer:**

> In one project, we underestimated the complexity of integrating a new frontend feature with an existing backend API. Initially, we expected the API contract to be straightforward, but during integration we discovered several edge cases that weren't covered in the original requirements.
>
> My role was primarily on the frontend, and I was responsible for integrating the API and building the UI.
>
> As the issues became clear, I worked with the backend developer to clarify the API contract and we adjusted the implementation. However, the original timeline had to be extended.
>
> Looking back, I think we should have validated the API contract and identified the edge cases earlier instead of assuming the integration would be simple.
>
> The main lesson I learned was to identify technical dependencies early and include integration work in the initial estimation.

**Strong takeaway:**

> "The project didn't go as planned, but it helped us improve how we estimate and validate dependencies."
